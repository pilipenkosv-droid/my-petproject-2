# ADR-014 — pipeline-v7: эксперимент «Prettier для OOXML»

- Дата: 2026-09-12
- Статус: **accepted (2026-09-14)** — весь ГОСТ-трафик через v7 по решению владельца; v6 остаётся как fallback при любом сбое v7 (`PIPELINE_V7_PERCENT=0` выключает без деплоя)
- Связанные: [ADR-012 — post-MVP fixes](012-pipeline-v6-post-mvp-fixes.md), [ADR-013 — Template Registry](013-pipeline-v6-template-registry-and-rule-packs.md), план `~/.claude/plans/diplox-humming-honey.md`

## Контекст

Pipeline-v6 (template-first: mammoth → markdown → Pandoc `--reference-doc`) в проде с 24.04.2026. Оценки (`feedback`, avg по месяцам) идут вниз: 2026-03 (легаси) 2.15 → 2026-04 1.81 → 2026-05 (v6) 1.82 → 2026-06 1.50 → 2026-07 1.00. После v6 появились новые классы жалоб: «вместо таблицы палочки», «файл не открывается», «перепутал структуру», «сноски не выполнены», «ссылки поломаны». Архитектурная причина: markdown — узкое горло, всё, что не выражается в GFM (сложные таблицы, сноски, REF/PAGEREF, sectPr/колонки/колонтитулы), теряется безвозвратно — это свойство подхода, а не набор багов. Легаси (`src/lib/pipeline/`, preserve-order XML) сохраняет содержимое по построению, но медленно (12 стадий полного unzip→parse→build→zip) и не закончено (LLM-разметка не влезает в таймаут, `sanitizeDocumentDefaults` сама роняет `w:cols`). Анализ этих механизмов был сделан 09.07.2026 (`diplox/.claude/plans/2026-07-09-formatter-*.md`, 18 агентов) и не был исполнен — ни одного коммита.

Запрос продакт-оунера: «сделать попытку новой, точнее, новую версию сделать и проверить её работоспособность. Но это не означает, что мы будем её использовать. Это эксперимент.»

## Решение (эксперимент)

**Принцип: документ никогда не покидает OOXML.** Один parse → один serialize. Дерево содержимого (`document.xml` + footnotes/endnotes/headers/footers) неизменяемо; меняются только `styles.xml`, `pPr`/`rPr` каждого абзаца/рана, `sectPr` (поля и размер страницы с сохранением ориентации и колонок), `numbering.xml` (свойства уровней, новые `numId` не заводятся), плюс явно помеченные вспомогательные блоки. Ветка `w37/26-pipeline-v7-experiment`, не подключена к продовым роутам.

**Own zip writer.** Round-trip на нетронутых частях архива побайтно; JSZip не сохраняет побайтную структуру (STORE/DEFLATE, флаги, extra-поля) — `docx/zip.ts` копирует нетронутые entries verbatim и пересжимает только помеченные dirty.

**Фингерпринт верности.** Считается дважды из байтов (вход и выход, не из AST): упорядоченные блоки `{p: normalize(text), inTableDepth, hasDrawing, footnoteIds}` / `{tbl: shape}`; 20 счётчиков-маркеров (`w:tbl/tr/tc/drawing/…/sectPr`); инструкции полей REF/PAGEREF/SEQ/NOTEREF с аргументами; bookmarks; секции без размеров полей; media/rels/embeddings.

**Гейт с допусками A1–A7** — всё вне списка hard-fail, docx не пишется:
- A1 — вставки только внутри блока, помеченного `_dpx_aux_<kind>_<n>` (toc, caption); бюджет считается от того, что реально помечено.
- A2 — удаление одного непрерывного старого TOC (поле или стили TOC1..9 рядом с «СОДЕРЖАНИЕ/ОГЛАВЛЕНИЕ»), плюс маркеры/поля/закладки, которые он с собой уносит.
- A3 — удаление пустых абзацев, кап `min(30, 5%)` от числа абзацев в части, не в ячейках, без `sectPr`/anchor/drawing/embed.
- A4 — изменение текста только при включённой нормализации пробелов и только если строки равны после `looseEqual` (сейчас это единственная разрешённая текстовая мутация).
- A5 — ширины колонок таблицы (не количество колонок и не форма).
- A6 — переключатели полей `PAGE`/`NUMPAGES`/`TOC` свободны как презентационные; всё остальное (REF/PAGEREF/SEQ/NOTEREF) должно сохранить аргумент; висячие ссылки на пропавшие закладки — hard fail отдельно.
- A7 — один вставленный `w:sectPr` после титульной страницы, если он копия следующей секции (кроме `w:type`) — это разрыв страницы, не новая раскладка.

**Классификация T0** — 12 правил по фиксированному порядку, первое совпадение побеждает: `outlineLvl` → `pStyle` через `basedOn` к Heading (по `styleId` и локализованному имени — для LibreOffice/Google Docs) → toc-стиль → caption-стиль → `numPr` (заголовок либо список) → позиция (ячейка/сноска/колонтитул) → подписи «Таблица N —»/«Рисунок N —» → ГОСТ-разделы полной строкой → нумерованные заголовки `^\d+(\.\d+){0,2}\.?\s` → `m:oMath` → пустой → `unknown`. Затем два региональных прохода на весь документ (библиография, титульная область до первого H1/TOC) и когерентность уровней (заголовок не может углубиться больше чем на 1); если заголовками размечено >40% абзацев — `suspect`, все догадки, не подтверждённые `outlineLvl`/стилем, откатываются в `unknown`. Роли привязаны к узлу (`WeakMap`), не к индексу. `unknown` по умолчанию рестайлится как `body` — безопасное направление; отчёт хранит исходный вердикт.

**LLM-остаток** (реализован, живой прогон не сделан — см. «Что не проверено»): кандидаты только `unknown`/confidence <0.85 и структурно интересные (≤200 симв., bold/caps/центр/цифра-точка/нестандартный размер/keepNext); кап 600, батч 80, ≤8 запросов, 45 с суммарно. Выход модели — только `{i, role, confidence}` по enum, без текста; confidence <0.7 → `body` + запись в `lowConfidence[]`. Любая ошибка — `llmDegraded`, роли T0 остаются как есть.

**Restyle** — `styles.ts` (upsert `DpxBody/DpxHeading1..3/DpxCaption/DpxTocTitle` + docDefaults + встроенные Normal/Heading1..3, ничего не удаляется) → `sections.ts` (поля/размер во все `sectPr`, включая в ячейках, сохраняя ориентацию/колонки) → `paragraph.ts`+`runs.ts` на каждый классифицированный абзац (пишет и `pStyle`, и явные `w:spacing/w:ind/w:jc`, потому что чекер читает `pPr` напрямую, без каскада стилей; `rFonts/sz` перезаписываются, `b/i/u/vertAlign` в теле сохраняются, `w:u` снимается везде кроме toc — см. «Подчёркивание и цвет» ниже) → `tables.ts` (рекурсия во вложенные таблицы, `tblGrid`/`gridSpan`/`vMerge` неприкосновенны, первая строка получает `w:tblHeader`).

**Aux-блоки** — то, что рестайл не может дать, потому что студент это не писал: разрыв секции после титульника (A7), поле TOC `TOC \o "1-3"` с `w:dirty` (A1; статическое заполнение — на воркере, где есть soffice: сделано 19.09.2026, `aux/toc-static.ts`, см. ADR-016); идут после restyle, до save.

### Уточнение гварда «СОДЕРЖАНИЕ» (19.09.2026)

Коммит d7cf44c добавил гвард `tocContentSkip`: если в документе есть строка
«СОДЕРЖАНИЕ/ОГЛАВЛЕНИЕ», оглавление не вставляется вовсе. Он появился после двух
отзывов 1★ (D-1, D-6), где поле TOC печаталось поверх собственного текста
студента, и в этой части он остаётся.

Но отказ срабатывал по одному лишь наличию слова, независимо от того, есть ли
под ним перечень. На бенче это стоило 22 документов из 37 по критическому
правилу `structure.tocFieldCode` (было 4 в третьем прогоне): студент написал
заголовок и оставил под ним пустую страницу — форматтер уважал пустое обещание.

Уточнение: `toc-heading-present` остаётся отказом, только когда под заголовком
что-то перечислено — таблица, абзацы с ролью `toc` или больше одной непустой
строки до следующего заголовка (одинокая строка до 10 символов, вроде забытого
номера страницы, считается пустотой). Когда под заголовком пусто, вставляется
**только абзац с полем**, сразу под строкой студента: своего заголовка мы не
добавляем и чужой не двигаем. Телеметрия различает пути через
`aux.tocUnderExistingHeading`.

Исходный смысл D-1/D-6 сохранён: второго «СОДЕРЖАНИЕ» на странице не появляется
ни в одном из путей, а документ с настоящим оглавлением (поле, стили TOC1..3,
двухколоночная таблица pandoc) по-прежнему ловится раньше, как `existing-toc`.

Остаток после уточнения — 20 документов, и это уже граница чекера, а не гварда:
он признаёт оглавление только по полю `TOC \o` или стилям `TOC1..3`, а
набранное руками оглавление с точками-лидерами в тексте (весь synthetic-корпус,
`q39zp7HUjxvE`) для него не существует. Это отдельная задача.

### Подчёркивание и цвет (решение владельца, 19.09.2026)

`KEEP_UNDERLINE` сужен с `{toc, title_page}` до `{toc}`. Причина — прод
показывает пользователю `finalScoreUndef`, то есть чекер без ролей: исключение
«по роли title_page» не доходило до оценки, и каждый подчёркнутый run титульника
оставался провалом. Оговорка владельца: run, чей текст состоит только из
пробелов и подчерков (линия под подпись), теряет `w:u`, но сохраняет содержимое
и получает `xml:space="preserve"` — место под рукописную подпись на странице
остаётся. Цвет и выделение с этого же момента снимаются со всех run, включая
структурные и внутри гиперссылок.

## Что не проверено

- **LLM-остаток вживую.** Суточная квота Gemini free tier исчерпана; запись `gemini-2.5-pro` в реестре моделей — 404. Реализация есть, прогон нет.
- **Рендеринг в MS Word** — сверялись только через LibreOffice (`UpdateFields=true`); Word не запускался.
- **Поворот в landscape на реальных документах** — только на синтетическом `05-multi-section`.
- **A2 (удаление старого TOC) на реальных документах** — не встретился ни один реальный документ с существующим TOC в выборке; проверено только на синтетическом `10-existing-toc`.
- **`multipleSpaces` через границы прогонов** — не проверялось, что повторный прогон v7 поверх уже нормализованного документа стабилен (идемпотентность).
- **Библиография и нумерация** (`restyle/numbering.ts`) — за флагом, выключены в бенче.
- **Двойной подсчёт вложенных таблиц в статистике** — не измерено, влияет ли на `pages`/счётчики отчёта.

## Замечания ревью

Слепое ревью ветки (после третьего прогона): **эксперимент — SOUND-WITH-GAPS, к продакшену — не готов.**

Что подтвердилось: отпечаток считается из байтов, обход блоков универсальный (надписи, sdt, ревизии, `mc:AlternateContent`), zip-писатель копирует нетронутые записи побайтно, порядок детей OOXML выписан явно, каждое послабление гейта названо и механизировано. Диалога «Word обнаружил ошибку» ревью не нашло чем вызвать.

Что было дырами и закрыто в коммите `144f079`: допуски A2/A3 разрешали удаления, которых пайплайн не делает (теперь только по флагу `allowRemovals`); абзац с одной сноской считался пустым; табуляция и `w:sym` не входили в текст отпечатка; размер страницы принудительно ставился A4 (теперь только вблизи A4, `pgSz` в отпечатке); автоширинные таблицы с явными `w:tcW` растягивались на 100 % (теперь нет, сумма сетки в отпечатке, допуск ±2 %); `pageBreakBefore` снимался у тела; двойной разрыв после титульника; при титульнике-таблице содержание вставлялось перед ним (теперь без найденного титульника ничего не вставляется); «1.5 млн рублей» становилось заголовком (нужен сигнал формата); библиография открывалась только на L1; при `suspect` документ форматировался как сплошное тело (теперь отказ, exit 3).

Что осталось открытым: гейт по-прежнему слеп к `pStyle` и к раскладке страницы — «гейт зелёный» означает «текст и структура блоков сохранены», не «страница выглядит так же»; допуск A1 самоудостоверяющий (бюджет вставок строится из самих вставок; сегодня это два абзаца содержания); `w:altChunk`/`w:subDoc` не в отпечатке; LLM-слой не измерен на корпусе; сравнение чекера с v6 теперь like-for-like (оба без разметки), но критерий 4 «v6 проваливает гейт» — описание разницы подходов, а не доказательство преимущества.

### До перевода даже 10 % трафика (из ревью)
Флаг-гейт на удаления закрыт; нужны: визуальный постраничный диф до/после на всём корпусе; прогон с LLM-слоем (квота); ручная проверка 10 реальных документов человеком; shadow-режим на проде (считать v7 параллельно, не отдавая пользователю) с метрикой отказов и провалов гейта; тесты zip-писателя на data descriptor/STORE; решение о поведении при провале гейта в проде.

Что нужно до 10% трафика (черновой список, не решение о внедрении):
- Воркер на VDS (Этап C плана) — тяжёлая обработка (soffice для статического TOC, LLM-остаток) не помещается в текущий serverless-таймаут. **Сделано: ADR-016 (18–19.09.2026).**
- Смок-тест в MS Word, не только LibreOffice.
- Решение о поведении гейта в проде: ошибка студенту vs тихий возврат исходника без изменений.
- UI для низкой уверенности классификации (`lowConfidence[]`) — сейчас это только запись в отчёте.
- Rule-pack для методичек (ADR-013) поверх v7 — сейчас только ГОСТ 7.32.
- Смок-тест LLM-остатка, когда вернётся квота.

## Раскатка

v7 включается процентом задач, а не пользователей: `PIPELINE_V7_PERCENT` (целое 0–100, по умолчанию 0). Бакет считается от `jobId` (FNV-1a % 100), поэтому одна задача всегда идёт одной веткой, а бакеты вложены: кто попал в 10%, попадёт и в 50%. `PIPELINE_V7_FORCE=1` — локальная отладка, гонит через v7 всё.

Откат автоматический и молчаливый. Роут пробует v7 (`src/lib/pipeline-v7/try-v7.ts`) с таймаутом 40 с внутри `maxDuration = 60`; любой сбой — провал гейта верности, отказ классификатора, таймаут, исключение — логируется как `[v7] fallback <причина>` и передаёт документ в v6. Пользователь получает документ в обоих случаях; отдельного UI у эксперимента нет.

За чем смотреть в `job.statistics`:

- `pipelineVersion` — `"v6"` или `"v7"`, ставится всегда. Это ключ для джойна с `feedback.rating` по `jobId`: средняя оценка v7 против v6 на одном и том же трафике — единственный вопрос эксперимента.
- `v7Fallback` — почему v7 выбрали, но он не сработал: `gate`, `refused:classification_suspect`, `timeout`, `error:<Name>`. Доля fallback от числа выбранных задач — вторая метрика: она измеряет готовность гейта к реальным документам, а не к корпусу.
- `statistics.v7` (только при `pipelineVersion === "v7"`) — `gatePass`, гистограмма ролей и `suspect` классификатора, `formatMs`, `finalScoreUndef` / `finalScoreRoles`, `auxTocInserted`.

Порядок: начать с 10% и дождаться хотя бы полусотни оценок на ветку; поднимать только если доля fallback низкая, а средняя оценка v7 не ниже v6. Выключение — `PIPELINE_V7_PERCENT=0`, без деплоя.

## Как воспроизвести

```bash
# синтетический корпус (12 документов, коммитится в data/corpus/synthetic/)

# реальный корпус — читается из соседнего чекаута, 48ч TTL Supabase-бакета
npx tsx /Users/sergejpilipenko/diplox/scripts/pipeline-v7/fetch-real.ts --limit=20

# один документ
npx tsx scripts/pipeline-v7/run.ts <in.docx> <out.docx> --no-llm --json [--text-norm]
```
